## Production flow

A code/product push to `main` runs test and Playwright browser-smoke jobs. `deploy-cloudflare` runs only after both succeed. It rebuilds production assets, applies D1 migrations, deploys Cloudflare Pages + Functions, then health-checks `https://cymonia.pages.dev/api/health` for:

- `ok: true`
- `@cf/zai-org/glm-4.7-flash`
- `personal_agent_ai: workers-ai`
- `d1_bound: true`

State-only commits generated by the five-minute economy clock are excluded from CI/deploy through `paths-ignore`; the persistent world advances directly through the protected Cloudflare API instead.

GitHub Pages is manual-only and is not the canonical production surface.

## Browser / production verification boundary

Playwright is installed by GitHub CI. This packaging runtime does not have a working local Playwright installation, so this report does **not** claim a fresh local browser-smoke result for the new AI/deploy changes. The deployment job is deliberately gated on the GitHub browser-smoke job, so Cloudflare production cannot be released by this workflow until that runner passes.

The Cloudflare deployment itself also requires repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`, plus the existing runtime/scheduler secrets documented in `docs/deployment-cloudflare.md`.
